# 坡道区域保持与轨迹侧边约束修复（2026-11-02）

本轮修复后，原 RMUC 2025 的连续路线 **11/11 个目标到达，10/10 个上下坡段的业务检查通过**；200 项回归通过。额外的坡脚附近冷启动用例仍未到原目标，导航提前以安全接近/投射点完成任务，因此不能宣称所有启动位置和目标策略均已通过。

## 修改与依据

1. **跨重规划保持区域。** 原 `RegionController::setPlan()` 每次更换轨迹清空准备状态，语义窗轻微移动就会撤回跟随。现在按该区域已配置的 `release_distance`，在里程计位置邻域内保持最近的准备/激活状态；航向依据新轨迹当前切线重新计算。当前轨迹明确越过释放位置或清空计划时解除。区域在轨迹末端仍有效时另外保存有限释放距离，避免无穷大出口使保持失效。
2. **按制动距离提前准备对齐。** 准备距离取原配置与 `v * reaction_time + v² / (2 * deceleration) + stop_margin` 的较大值，复用现有目标接近制动参数。mode 激活、提交和退出边界保留。区域内暂时无有效航向时保持已发角度并清零平移。
3. **MINCO 使用同一份侧边掩码。** 第一次修改后，连续平台往返已通过，但中部目标仍因 `TERRAIN_SIDE_ENTRY` 超时。搜索与最终检查都能看到侧边格子，优化器原本只有占据 ESDF 代价，反复把搜索折线平滑进禁入格。现在增加同一掩码的有符号距离梯度和半个栅格的软缓冲；不改变侧边掩码、占据图、净空阈值或最终逐段检查。

主要代码为 `region_control.hpp/.cpp`、`nav_executor_node.cpp`、`terrain_semantics.hpp`、`minco_optimizer.hpp/.cpp` 与 `minco_planner.cpp`。仿真和实车继续使用相同导航配置；本轮没有调整固件、仿真物理参数、速度/加速度或碰撞净空。
