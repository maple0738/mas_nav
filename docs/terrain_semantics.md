# 实时与先验地形语义

导航的坡道约束共用 `buildSlopeSideMask()`：以坡道标签 `5` 的局部轮廓估算边界法向，并用上升向量或先验图的长轴区分两端和两侧。坡面两侧紧邻的普通格成为一格宽的硬障碍带，坡道入口和出口保持开放。侧边障碍进入先验规划约束或在线累计占据图；在线 ROGMap 搜索、局部路径处理和最终轨迹校验也检查同一障碍带，斜穿角点时连同两个相邻格一起检查。已有障碍和净空规则仍适用。

## 在线建图

ROGMap 在薄地面邻域拟合高度平面，得到坡道标签及指向高度增加方向的单位向量，目前自动识别坡道 `5` 和隧道候选 `6`。`OnlineGlobalMap` 可累计观测到的特殊地形 `5/6/7`（`7` 的在线识别尚未实现）到 odom 坐标系。特殊标签需要连续 3 份新快照确认后才写入累计图；离开局部窗口或收到未知观测不会清除它。原位置连续 10 份完整普通地面观测会清除已记忆标签，供误识别纠错。两个次数由 `planner.online_global_map.terrain_confirmations` 和 `terrain_clear_confirmations` 配置，观测间隔受 `confirmation_max_gap_s` 约束。实时局部占据障碍仍即时生效；累计标签确认前，区域 mode 可能暂按普通地面处理，需要在实车坡道入口检查识别提前量。在线累计占据图 `/nav_executor/online_global_map` 将已确认坡道的侧边格显示为障碍，`/nav_executor/online_terrain_map` 用于底盘区域模式，并发布 `/nav_executor/online_terrain_uphill`（`32FC2`，每格两个 `float32`，单位向量）供检查。RViz 默认显示 `/nav_executor/online_terrain_markers` 的累计区域，旧的 ROGMap 局部标记仍可用于核对当前视野。累计数据属于本次进程，重启后重新建图；不能把它当作跨次运行的持久地图。

## 先验地图

`map_server` 仍接受原有仅含 `width`、`height`、`resolution`、`terrain` 的 msgpack。可以额外提供 `uphill`：长度为 `2 × width × height` 的一维数值数组，按行优先排列，每格依次为 `x, y` 两个分量。坡道格填入指向高度增加方向的单位向量，其他格填 `0, 0`。地图服务检查数组长度、有限性、向量长度和非坡道格的零向量要求，并通过 `/terrain_uphill_map`（`32FC2`）发布。数组与地形标签、代价图共用尺寸、分辨率、原点和 frame。

旧地图没有 `uphill` 时，地图服务从每个至少 16 格且明显狭长的坡道连通区域计算长轴。这个轴线可用于生成两侧障碍带，**不能区分上坡与下坡**。近方形、断裂或分叉区域没有可靠长轴时，方向为零，这些格不会启用侧边障碍；需要准确上升方向时，应从高程数据或人工标注补充 `uphill`。坡道范围和向量应与地图坐标系一致；实车应核验入口边界、侧边障碍和车辆转弯半径。
