# 坡道前贴边与方向地形方案对照（2026-11-02）

用户反馈：GUI 复跑中，上坡前的轨迹贴着平台/坡道边缘走，而坡道前方有明显空地。
本轮先对照 `reference/` 与 `components/` 的现有实现，再做了一个最小原型验证。

## 参考项目里的成熟方案

### hw-sentry-26（本仓库的直接上游）

这是唯一把“坡道方向”写成规划约束的参考实现：

- `nav_executor/config/path_planner.yaml:13-15`
  - `directional_terrain.min_alignment_cosine: 0.8`
  - `directional_terrain.runup_transition_distance: 0.1`
- `nav_executor/config/terrain_traversal.yaml`：slope 的 `run_up: 0.2`，即坡道物理边缘
  上游 0.2 m 作为助跑对齐区。
- `nav_executor/src/path_planner/search/grid_utils.cpp:37-76`
  - `directed_terrain_edge_allowed()`：只要边的一端是坡道本体，就要求运动方向与坡向
    的绝对余弦 ≥ 0.8；两端同属坡道时还要求同一上下坡方向。
- `nav_executor/src/path_planner/search/reference_path.cpp:327-334`
  - 用 `runup_distance_gate(distance, run_up, transition)` 把坡道上游的助跑区标成
    “方向 + 速度窗 + gate”，让参考路径提前直行对准坡道。
- `nav_executor/src/path_planner/trajectory/minco_optimizer.cpp:418-460, 784-800`
  - 沿前方弧长积分“地形暴露量”，在 run-up 区内加 `κ²` 正则和方向代价，
    使 MINCO 平滑后的轨迹也提前对准，而不是贴着坡道侧边切进去。
- `map_server` 发布三通道方向图（角度/幅值/标签），并对方向场做膨胀；执行器用
  `DirectionMap` 采样方向、标签和幅值。

它的关键点不是“把台阶边缘当成一个更远的障碍”，而是：
1. 坡道有明确的通行方向；
2. 搜索和最终轨迹都要求进入坡道时航向与坡向对齐；
3. 助跑区从坡道上游延伸 `run_up`，在到达坡道前就完成直行对准。

### 其他参考

- `pb-2025`、`qdu-2026`、`hero-2026`：Nav2 的 `inflation_layer`，半径分别约
  `0.7 / 0.6 / 0.40 m`，只提供离障碍物的距离代价，不知道坡向或坡道入口。
  它们能让路径离墙远一点，但不能保证从坡道正前方进入。
- `rose-navigation`：有坡度地图（`map/rose_map.cpp` 的 `max_slope_deg`），但没有把
  坡向写进路径搜索或轨迹验收。
- `navi-minco-bit`：有 `SimpleCorridorGenerator`（机器人半径 0.4 m + 余量 0.15 m），
  用安全盒约束 MINCO；它是通用的走廊净空，不区分坡道方向，可作为补充层。
- `components/`：主要是定位、建图、局部地图和驱动，没有坡道接近方向的规划实现。

## 已做的原型

在现有简化执行器上增加了三个软代价，硬安全门不变：

- `global_path_searcher.cpp`
  - `path_height_penalty`：按累计图高度边缘距离，给 A* 路径加 20 倍软代价；
  - `slope_alignment_penalty`：当目标格是坡道（label 5）时，按
    `max(0, 0.8 - |heading·uphill|)` 加 30 倍软代价。
- `minco_planner.cpp`
  - 高度边缘约束的距离减去 `max(safe_dist, height_clearance) - safe_dist`，
    让优化器偏好 0.45 m 的边缘余量；最终碰撞/台阶硬门仍是原阈值。

这相当于 HW 方案的一个简化版：只做“软对齐 + 高度边缘软偏好”，没有移植
`DirectionMap`、run-up gate 和 MINCO 的 run-up 曲率/方向正则。

## 原型结果

独立域 174、无头、红方基地→蓝方基地→红方基地：

| 指标 | 原型（153544） | 上一版最好（150242） |
| --- | ---: | ---: |
| 去程 / 返程 / 往返 | 100.74 / 75.18 / 175.92 s | 60.30 / 62.04 / 122.34 s |
| 去程 / 返程轨迹长度 | 85.39 / 54.55 m | 54.24 / 52.18 m |
| 坡道附近最小台阶中心距 | 0.542 / 0.556 m | 0.380–0.497 m |
| 跨 >8 cm 台阶 | 0 | 0 |
| 坡道/跟随/航向就绪 | 通过 | 通过 |

轨迹形状上，原型从北侧贴边改为从坡道前方下层平台（约 `y≈3.2`）绕入，坡道附近
确实用上了空地；但整条路线变长，往返时间比上一版最好结果多约 54 s。一次结果不能
区分“软代价导致绕路”和“首次探索方差”，也不能据此宣称稳定改善。

`build/mas2027_nav_executor` 的 11/11 CTest 通过；本轮只验证红蓝基地一条路线，
实车未运行。原型权重目前是硬编码，尚未做成参数，也未移植 HW 的硬对齐和 run-up gate。

### 定向 run-up 试验（第二次，已回退）

按“只在上游 0.30 m 内加方向代价”的思路又做了一版：删除全局高度边缘代价，
仅在坡道单元周围 0.30 m 内，对 `|heading·uphill| < 0.8` 的步长加 30 倍软代价；
MINCO 的高度偏移也撤回。构建和 11/11 CTest 通过。

无头复跑（`reports/rerun-20261102-154543`）在坡道和下层平台段正常，但到中央高地
`(17.99, 8.44)` 后连续约 60 s 报
`Online search has no reachable observed subgoal ...`，位置几乎不变，没有自行恢复；
为避免继续占用仿真资源，手动终止。该状态与旧版偶发的“高地上无前沿”死锁相似，
但这次没有在 60 s 内恢复，不能作为可用方案。

### 硬方向约束试验（第三次，已回退）

最后一版按 HW 的 `directed_terrain_edge_allowed` 做硬约束：`online_edge` 只要一端是
坡道本体，就要求运动方向与坡向的绝对余弦 ≥ 0.8；移除了所有高程/run-up 软代价。
构建和 11/11 CTest 通过，无头复跑（`reports/rerun-20261102-155054`）中坡道段没有出现
方向拒绝，但路线改为先绕到 `(6.0, 1.16)` 的西侧坡道，再上中央高地；到 `(17.5, 8.0)`
附近再次停顿，约 20–30 s 没有明显推进，手动终止。硬方向没有解决“高地上无前进子目标”
的根因，反而把入口限制到更远的一侧。

三次试验的结论：
- 全局高度边缘软代价能把轨迹推回坡道前方空地，但路线明显变长（175.92 s）；
- 只在坡道附近加 run-up 软代价，仍会在中央高地 `(17.99, 8.44)` 触发约 60 s 的
  “无可达观测子目标”；
- 硬方向约束能阻止侧向进入，但会把入口推到更远的坡道，并在高地上继续卡住；
- 仅做局部补丁没有复现 HW 的“对齐进入 + 不增加长绕路 + 不失稳”，说明需要把
  方向图、run-up gate、MINCO 暴露量正则和死胡同恢复一起移植，不能只摘一条规则。
- 全局高度边缘软代价能把轨迹推回坡道前方空地，但路线明显变长；
- 只在坡道附近加 run-up 软代价，仍可能在中央高地触发无可达子目标；
- 仅靠软代价没有稳定复现 HW 的“对齐进入 + 不增加长绕路”，需要把方向图、
  run-up gate 和 MINCO 暴露量正则一起移植，或至少把硬方向约束和恢复逻辑一起做。

## 建议

如果目标是“既贴边改善又不明显拖慢往返”，建议按 HW 参考的做法做定向移植，而不是
继续加全局软代价：

1. **硬方向约束**：在 `global_path_searcher` 的坡道边和 `validateTrajectory` 的坡道
   采样段要求 `|heading·uphill| ≥ 0.8`（可先加参数，默认关闭）。
2. **run-up 区**：只在坡道物理边缘上游 `0.2 m`（斜率）内加方向/曲率代价，不要把
   整个平台边缘都当成高代价区。
3. **MINCO run-up 正则**：移植 `runup_distance_gate()` 和
   `minco_optimizer` 的暴露量积分，让平滑器在坡道前直行，而不是在坡道口急转。
4. **回归**：用合成坡道 + 一条会从侧面进入的路径，验证旧实现失败、新实现选择
   正前方入口；同时保留现有台阶/净空硬门。

当前源码已回退到已验证的 122.48 s 配置并重新构建；三版坡道贴边试验只保留在这里
作为记录，不进入最终配置。
